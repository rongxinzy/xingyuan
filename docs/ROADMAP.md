# 行远第一阶段

目标：在 MonoCode 原生交互中，用 Pi 驱动一个本地模型完成任务。

## 本次实现

- 行远产品名、独立 Tauri identifier 和应用数据目录。
- 项目内锁定 Pi CLI 1.0.0；开发模式优先解析本项目的 CLI。
- Pi 的配置、认证和会话使用应用数据目录下的 `pi/agent`。
- 设置页的用户级 Pi 技能发现与原生运行时共用 `pi/agent/skills`，不回退到用户旧 Pi 目录。
- 本地模型设置页选择 llama-server 和 GGUF，保存配置、启停、显示状态、打开日志。
- llama.cpp 仅绑定 `127.0.0.1`，固定模型 alias，启用原生 Jinja 模板与工具协议。
- Pi 原生 models.json 注册本地提供商；不覆盖用户后来在行远中增加的其他提供商。
- 退出应用回收本次启动的 llama.cpp；端口占用时拒绝启动，保留其他服务。
- 桌面构建携带固定版本的 Pi 独立二进制与 llama.cpp 官方包，下载与缓存校验 SHA-256 和大小，保留配套库及许可证。
- 安装包内自动解析运行文件；内置 llama-server 路径不持久化，支持应用移动或 AppImage 挂载路径变化。托管 Pi 不走 CLI 自更新。
- 三个平台 CI 增加未签名调试包构建，不发布安装包。

## 第一轮验收

1. 应用显示「行远」，设置页可以打开本地模型配置。
2. 选择有效运行文件和 GGUF，保存后 Pi 能发现 `xingyuan-local/local-model`。
3. 模型运行后，新建 Pi 会话并完成一次真实回复；对支持工具调用的模型另验收一次文件读写。
4. 加载过程中可停止；失败有错误与日志，端口冲突不能破坏其他服务。
5. 关闭和重新打开会话可恢复 Pi 原生历史；退出应用没有残留本地模型进程。
